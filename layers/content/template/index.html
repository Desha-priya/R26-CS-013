Reported limitations

Disclosed for evaluation transparency

Video dataset overlap. The FaceForensics++ subset was a single pool without pre-defined split. Held-out numbers are on a fixed seeded 30% split; if the CNN was trained on the same pool, some overlap with training is possible.

Class imbalance in audio eval. ASVspoof 2019 LA eval is dominated by spoof examples (63,882 vs 7,355). Both the naive 0.5 threshold and the EER-calibrated operating point (0.002) are reported; production uses the calibrated threshold.

Real-time capture pipeline unvalidated against live traffic. Detection models are validated on offline test sets. IMAP watcher and WASAPI-loopback call monitor are working prototypes tested with synthetic inputs; live end-to-end validation is future work.

Before you continue

How this layer handles the content it analyses

What this system does

This layer analyses email text, video, and audio to detect phishing, deepfake video, and cloned/synthetic voices. It can do this two ways: content you upload directly here, or — if enabled — automatically, by monitoring a connected mailbox and/or live call audio in the background.

Automatic monitoring status

Mail watcher — checking… Call monitor — checking…

Mail monitoring only runs once you connect a mailbox in Automatic Monitors. Call monitoring is off by default and only runs if you explicitly turn it on there, because it captures live system audio and on-screen video during a call — a meaningfully more sensitive capability than checking an inbox.

What is captured

  • Manual analysis: the specific email text, video, or audio file you submit
  • Mail watcher (if enabled): the text of new emails in the connected mailbox
  • Gmail sign-in, drop-folder and notification watchers (if enabled): the text of new emails — or, for the notification watcher, only the sender, subject and preview shown in mail notifications (notifications from every other app are ignored)
  • Call monitor (if enabled): system audio and periodic screenshots of the call window while a call app is running

What is NOT kept

  • Raw content (the email body, the video/audio file itself) is deleted immediately after it is analysed — it is not stored
  • Only the decision (risk score, real/fake, phishing/normal) and metadata are retained, in a signed, tamper-evident alert log
  • No email, video or audio content is sent to any cloud AI service — all analysis happens on this machine. (If you sign in with Google or connect a mailbox, NeuraShield fetches your mail from that provider the same way a mail app would; Google access is read-only and can be revoked with Sign out.)

Your controls

  • Turn mail and call monitoring on or off any time in Automatic monitors — nothing runs without you enabling it there
  • You can view every alert this layer has produced in Alert history
  • When a threat is detected, you'll see a live notification with guidance — acknowledging it is recorded in the tamper-evident audit log

This notice reflects the current build's actual behaviour. For deployment beyond a demo/research setting, formal user consent and a data retention policy should be established.
